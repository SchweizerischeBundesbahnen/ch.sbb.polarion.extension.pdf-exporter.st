# CLAUDE.md

- Use `uv` for all Python tooling (`uv run tox`, `uv run pytest`, `uv sync`, `uv build`) — never `pip`, `python -m pip`, or bare tool invocations.
- GitHub Actions workflows from `SchweizerischeBundesbahnen/*` are intentionally pinned to `@main`, not hash-pinned. This is enforced by `zizmor.yml`. Do not change these to hash pins.
- CI uses `uv sync --frozen` (not `--locked`). Do not change back to `--locked`.
- `==` pins in `pyproject.toml` are for Renovate — `ruff`, `mypy`, `types-requests`, `pypdf`, `PyMuPDF`, `opencv-python-headless` and `testcontainers` use exact pins so Renovate creates PRs that go through CI. Do not relax these to ranges. Range-pinned deps are upgraded by `uv lock --upgrade`.
- **The last three of those decide test outcomes, not only the build.** `PyMuPDF` rasterizes every page the snapshot tests compare, so a bump moves the expected PNGs; `opencv-python-headless` compares them; `testcontainers` typing decides whether the `# type: ignore` in `tests/verapdf_manager.py` is needed. Range pins let all three arrive inside one lock-file-maintenance PR, which is how that PR stayed red from July to August 2026.
- **Python version is hardcoded in multiple places** — `.tool-versions` is the source of truth, but `pyproject.toml` (`requires-python`, mypy `python_version`) and `sonar-project.properties` must be updated manually. Only `ci.yml` reads from `.tool-versions` automatically.
- **System tests run in two places.** GitHub Actions (`system-tests.yml`) is the PR merge gate and runs against a containerized Polarion. The `Jenkinsfile` runs the same suite nightly against a long-lived Polarion environment. Keep these two paths in sync when changing test invocation or dependencies.
- **A run takes suites, and each test class states its suite.** `tests/suites.py` defines them: `default` (Polarion and WeasyPrint alone), `bulk` (the bulk processing service too) and `verapdf` (the PDF variant tests, long). A class states `SUITE` (`BulkProcessingTestCase` and `PdfExporterBulkProcessingAuthTest` state `bulk`, the variant test classes `verapdf`); one which states none is in `default`. `SYSTEM_TEST_SUITE` names the suites of a run, separated by commas, or `all`; where it names none, the run takes `default`, so a local run needs no bulk processing service and skips the long variant tests. `system-tests.yml` runs `default,bulk` and `verapdf`, the `Jenkinsfile` `all`, and `tox.ini` passes the variable through. A new test needs no list in a workflow: its class states its suite. A new suite needs its name in `SUITES` and in a run of the matrix in `system-tests.yml`; `all` takes it for Jenkins by itself. `tests/run.py` fails a run where a class states a suite of no other name. `SYSTEM_TEST_MODULES` narrows a run to modules, for a local run.
- **The Jenkins job is a multibranch pipeline.** Scheduled/manual stages in the `Jenkinsfile` MUST be guarded with `when { branch 'main' }` (combined with the `triggeredBy` checks) — otherwise the suite runs on every feature and PR branch. Do not assume a non-multibranch job; a missing branch guard means the tests fan out across all branches, not that they are skipped.
- **The nightly `Jenkinsfile` cron is intentionally time-based, not an upstream trigger.** The environment it tests is refreshed by a separate, externally scheduled process that Jenkins cannot observe via an upstream-job dependency, so the cron is timed to start after that refresh completes. Do not "improve" it into an `upstream(...)` trigger.
- **The harness must own the Polarion container, not the runner.** The merge gate reaches WeasyPrint over TLS with an API key, and the three things that makes possible are applied while `TestContainersHelper` creates the container: the property naming the secret, the authority in the JVM truststore, and the key seeded into the store before Polarion starts. Passing `TC_POLARION_SUT_URL` instead — GitHub Actions service containers, or any pre-started Polarion — takes the SUT branch of the harness, which applies none of them and says so only in a log line. The authenticated cases then skip rather than fail, since `containerized_run()` keys on `TC_POLARION_IMAGE_NAME`, and the gate goes green having covered nothing. Move the image pull off the critical path some other way (pre-pull in the background), or apply all three yourself, before Polarion reads them: it reads its properties and its secrets once, at start, so a provisioning step has to put them in place and then restart it, with the care the next bullet describes.
- **Never restart Polarion before its first boot has finished.** A restart issued mid-boot cannot shut down gracefully: the shutdown listener is not up yet, the container is SIGKILLed, and the index is left dirty. Polarion then reindexes in the background during the run and every test is about 1.7 times slower. Wait until `/polarion/` answers 200/301/302 before touching it, give `docker restart` a generous `-t`, and check the log for `Polarion could not be stopped` afterwards: that line means the tests are about to run against a recovering instance.
- **The PR merge gate is the GitHub Actions `system-tests` checks, not Jenkins.** `main` branch protection (ruleset `main-requires-status-checks`) requires the jobs `system-tests` and `system-tests-verapdf` to be green. Because Jenkins now only runs system tests nightly on `main` (the stage is guarded to that branch), it does NOT post a per-PR status — so the required checks must stay these GitHub Actions jobs. If you rename one of them or the workflow, update the required-status-check context in the ruleset in the same change, or PRs will be ungated (a renamed/missing required check can pass vacuously) or blocked. The job runs twice, each passing `SYSTEM_TEST_SUITE` (read by `tests/run.py`): `system-tests` runs the suites `default` and `bulk`; `system-tests-verapdf` runs the suite `verapdf`, the PDF variant tests, alone. weasysvg, the only SVG renderer of the service, draws every expected page. A new run that has to block a merge needs its name in the required checks of the ruleset.
